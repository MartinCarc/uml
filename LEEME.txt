USO DE OPTION FILE
Todos pueden consultar el catálogo, incluso visitantes. Buscá por nombre/apellido o ID; filtrá por equipo del EDIT (incluido Sin equipo), posición natural o alternativa, edad y media; recorré las páginas y abrí la ficha. Se mantienen el diseño y los estilos de UML.
La ficha contiene únicamente los datos acordados: información personal, ID, posiciones, forma física, pierna menos hábil, tolerancia a lesiones, actitud ofensiva/defensiva, los 23 atributos y las tarjetas especiales en español. No hay Datos adicionales del EDIT ni campos de cara/pelo/botines/animaciones/precio interno.

La media usa el cálculo principal de PES 2013 Editor 2.0 según la posición registrada: Havertz SD=83, Leno ARQ=76 y Robinson LI=94. No se utiliza el promedio entre paréntesis. El editor da 100 a Barella y Maradona en este archivo: se conserva ese cálculo y se muestra rojo, sin rebajarlo artificialmente a 99.

POSICIONES EN TODA LA APP
ARQ naranja; DFC/LD/LI azul; MCD/MC/MD/MI/MCO verde; SD/DC/ED/EI rojo. En Formación los colores del equipo se conservan en ficha y nombre; la posición tiene su propio distintivo claro. SWP del EDIT se agrupa como DFC.

ARMAR LOS PLANTELES INICIALES UML
En una temporada EN PREPARACIÓN:
Admin → Jugadores → Elegir desde Option File.
Elegí el equipo UML de destino, seleccioná el club del EDIT (o buscá jugadores), marcá a quiénes incorporar y revisá valor inicial y dorsal UML antes de confirmar. La selección por página permite incorporar el plantel del club completo o una parte, sin superar los cupos.
También hay un acceso Plantel desde Option File en Admin → Clubes y DTs.
Se conserva Agregar jugador manualmente. Para unir uno de esos jugadores con su registro del EDIT, abrí su ficha de Option File y usá Vincular a un jugador UML existente. La app no lo vincula automáticamente por nombre.
No se crean duplicados de un ID ya registrado en la etapa actual. No se reemplazan ni vacían planteles existentes. Archivar una etapa conserva su historial y permite reutilizar los IDs en la nueva; esa acción no se ejecuta durante la instalación.

ACTUALIZACIONES DE MITAD Y FINAL DE TEMPORADA
Volvé a Actualizar Option File, subí el nuevo CSV y revisá antes de confirmar. NO necesitás pasarle el archivo a Codex ni tocar GitHub para estas actualizaciones.
La versión nueva se publica de una sola vez. Una carga incompleta, inválida o cancelada no sustituye el catálogo vigente ni modifica planteles. Se guarda un historial de versiones. Volver a subir el mismo archivo vigente no duplica versiones, operaciones ni pagos.

La sincronización usa el ID del EDIT y modifica únicamente datos deportivos: nombre, edad, posición natural, media calculada, habilidades, tarjetas y los datos personales seleccionados.
Conserva los UUID UML, equipo actual, cesiones, valor económico del DT, dorsal, transferencias realizadas, operaciones pendientes, presupuesto, dinero, resultados, sanciones, formación y retiros. No ejecuta operaciones de mercado ni funciones de cobro/pago. Las temporadas cerradas conservan sus snapshots.
El club que figure en el CSV NO mueve al jugador en UML. Se muestran las diferencias para revisión y se señala si tiene una operación pendiente. Si un ID desaparece, el jugador UML y sus últimos datos se conservan; no se elimina. Si se cambia un ID del EDIT, habrá que revisar su vínculo.

Los 25 jugadores del Fulham de prueba que ya cotejamos se vinculan por sus UUID/nombres/club verificados. La primera publicación actualizará sus datos deportivos desde el archivo; por ejemplo, la media recalculada de Castagne es 78 en este CSV. Sus valores económicos y dorsales se conservan. Jugadores manuales que no coincidan con esos vínculos se revisan explícitamente desde el catálogo.
